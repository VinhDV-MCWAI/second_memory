# public-site (public pages, Astro)

The site visitors use without signing in ([ADR-0019](../docs/adr/0019-public-user-frontend.md)). Behaviour and rules: [docs/features/trang-public.md](../docs/features/trang-public.md).

- Astro, server output (`@astrojs/node`, standalone), served at the root `/` (ADR-0021: nginx sends `/admin`, `/_next/`, `/favicon.ico` to the admin app, everything else here). Every page path comes from `src/lib/routes.ts` (never build links from `import.meta.env.BASE_URL`: with base `/` that gives `//host`-style URLs). Old `/skills/me|account/*|files/*` addresses are `redirects` in `astro.config.mjs`. Pages render HTML on the server; the only client code is the end-user part (ADR-0020): `src/scripts/user-api.ts` (session cookie + XSRF like the admin app, marker cookie `sm_user` so guests make no API call), `account-link.ts` (header), `save-buttons.ts` (☆ / 🔖 of `SaveButtons.astro`: article public key), the scripts of `account/login`, `account/register`, `me`. Their forms go through `src/scripts/live-form.ts` (`liveForm(form)`): the inputs' required / minlength / maxlength / pattern attributes (kept equal to the API rules) plus `data-match` / `data-differ`, a message under each field once it is left, submit off until valid, `showServerErrors` puts 422 messages under their fields. Plain TS, no React; ~3 KB on an article page. Pages must stay readable without JavaScript.
- Pages (ADR-0022): `src/pages/index.astro` (forum-like home: one table per group, one row per category), `src/pages/categories/[slug].astro` (group or category; sort tabs, title search and second-category filter as a plain GET form, paging; the query is checked in `src/lib/category-query.ts` so the API never answers 422), `src/pages/articles/[slug].astro` (three columns: `ArticleMenu` (book tree via the recursive `BookTree`, or related articles; a `<details>` menu on phones), body, "On this page"; previous / next). `articles/[slug].astro` also reports a view (`reportView` in `public-api.ts`: POST, not awaited, errors swallowed, 2 s timeout; visitor = sha256 of nginx's `X-Real-IP` + user agent). `src/pages/search.astro` (GET form; queries the API would refuse with 422 are answered on the page), plus a search box in `Base.astro`'s header. Private or missing → same 404. Safe HTML from the API goes through `src/components/RichHtml.astro`: it splits out `<pre><code>` blocks (`src/lib/code-blocks.ts`) and colours them with Astro's built-in `<Code>` (Shiki, dual theme via `--shiki-*` variables in `global.css`; no extra dependency); the rest is printed with `set:html` and styled by `.article-body`. Also `src/pages/files/[key].ts` (fresh signed MinIO link per click, 302, `no-store`), `src/pages/healthz.ts` (container healthcheck, never calls the API: nginx starts after this container).
- `src/lib/public-api.ts`: server-only client for `GET /api/public/*`, answers kept 60 s (the API rate-limits per IP and every call comes from this server). Base URL `API_INTERNAL_URL`, default `http://ml-nginx:8080/api`.
- Types come from `laravel-api/openapi.json`: `src/types/openapi.d.ts` is generated by `make openapi` (`pnpm gen:api`); never edit it by hand.
- Styles: Tailwind 4 through `@tailwindcss/vite`, tokens in `src/styles/global.css`; light / dark follow the system setting (no theme switch).
- Production build bundles every dependency into `dist/` (`ssr.noExternal`), so the image (`docker/public-site/Dockerfile`, target `production`) holds only `dist/`.
- Dev: container `ml-public-site` (port 4321, host 3002), through nginx at http://localhost:81/ (port 3002 only for debugging: no admin, no API). Vite's dev files (`/@vite/`, `/src/`, `/node_modules/.vite/`) reach it through the catch-all; the nginx dotfile rule spares `.vite/`. `pnpm dev` runs `astro dev --ignore-lock`: Astro 7 writes `.astro/dev.json` (pid of the running server) into a volume that survives container restarts, and a stale one made the container refuse to start.
- Checks: `docker exec ml-public-site pnpm typecheck` (`astro check`), `pnpm format:check`; `make e2e` covers the pages. No ESLint: `eslint-plugin-astro` needs ESLint 10 and the workspace is on 9.
