# nextjs-fe (admin dashboard)

Client-rendered admin panel for the Laravel API. Conventions: `.claude/rules/frontend-nextjs.md` (auto-loaded for `src/**`).

## Commands

```bash
docker exec ml-nextjs pnpm lint            # eslint (flat config, eslint-config-next + prettier)
docker exec ml-nextjs pnpm typecheck
docker exec ml-nextjs pnpm test --run      # Vitest 4 (jsdom)
docker exec ml-nextjs pnpm format:check    # Prettier (.prettierrc.json)
```

## Layout

- `src/app/admin/<entity>/page.tsx` — one `'use client'` page per entity: list + filters + dialog form. Routes are in `ADMIN_ROUTES` (`src/shared/config`).
- `src/shared/api` — axios client (`client/`, Sanctum session cookie + XSRF header; a 401 calls the handler the auth provider registers with `apiClient.onUnauthorized`) and `API_ENDPOINTS`. Error toasts are shown by callers via `getApiErrorMessage` (`src/shared/utils/error-handler.ts`).
- `src/shared/hooks` — `useApiData` (list query), `useCrud` (mutations), `useActionLock`. Query keys come from `queryKeys` (`src/shared/api/query-keys.ts`).
- `src/shared/services` — service classes per module (`modules/auth.service.ts`: CSRF cookie → login, logout, me).
- `src/proxy.ts` — route guard: `/admin/*` (except `/admin/login`, `/admin/401`, `/admin/500`) without the Laravel session cookie redirects to `/admin/login?redirect=…` (presence check only; the API validates the session). Pages with the admin shell live in the route group `src/app/admin/(panel)/` (its `layout.tsx` is the shell); login and error pages sit beside it without the shell. nginx sends only `/admin`, `/_next/` and `/favicon.ico` here (ADR-0021).
- `src/shared/types/openapi.d.ts` — **generated** from `laravel-api/openapi.json` (`make openapi` regenerates spec + types; CI fails when stale). Never edit it; `types/models/*` alias its Resource schemas (`AdminMst`, `RoleMst`, `HistoryRecord`, …).
- `src/shared/types`, `src/shared/enums`, `src/shared/config` — UI types, enums mirrored from the backend, constants.
- `src/components/ui` — shadcn primitives (generated; edit sparingly). `src/components/common` reusable widgets, `src/components/layout`. Feature code lives in `src/features/{history,ledger,master,media,system}`.
- Dialogs: use `AppDialog` (`src/components/common/app-dialog.tsx`): `title` / `description` header with X, scrolling body, footer = Cancel + an `actions` array (label, onClick or `form` id, variant, size, permission; at most `DIALOG_DEFAULTS.MAX_ACTIONS`). Pass `dirty` to ask before discarding unsaved changes. Entity forms (`ResourceFormProps`) render no buttons: they set `id={formId}` and report `{ pending, dirty }` via `onStateChange`. Confirm prompts stay on `ConfirmDialog`.
- Live notifications (ADR-0014): `src/shared/realtime/echo.ts` (one laravel-echo + pusher-js connection to Reverb through nginx on the API host; channel auth via raw axios to `/broadcasting/auth`; off without `NEXT_PUBLIC_REVERB_APP_KEY`). `features/system/components/background-task-listener.tsx` (mounted in `AdminLayout`) toasts `background-task.finished` on `admin.{id}` and, once subscribed, asks `background-task/status/{id}` about ids in `pendingTasks` (sessionStorage) so a missed event still shows. A screen that starts a task calls `pendingTasks.add(id)`.
- File upload (ADR-0014): `features/media/lib/uploader.ts` `uploadFile(file, { folder, onProgress, signal })` — ≤ 100 MB one presigned PUT then `media/complete`; larger in server-sized parts, 4 XHR PUTs at a time (XHR for upload progress), part URLs fetched in batches of 100, retries with backoff (403 → fresh URL), aborts the server upload only when cancelled (after one part fails for good the other workers stop, checked before every attempt; a failure keeps the parts; `resumeId` continues an upload from `media/multipart/unfinished`, sending only the parts `media/multipart/resume/{id}` lacks; the file's `lastModified` is kept in localStorage to refuse a different file), returns `{ kind: 'processing', task }` (add `task.id` to `pendingTasks`). ETags are read from MinIO's response, which works because nginx serves MinIO on the same origin.
- Files screen (`app/admin/files`, `features/media/components/media-browser.tsx`): the open folder is the `folder` query param (wrap in `Suspense`, it uses `useSearchParams`); `useMediaList` / `useMediaActions` (`hooks/use-media.ts`), `PreviewDialog` (`preview-dialog.tsx`: `usePreviewUrl` asks `download-url/{id}?inline=1`, keyed apart from the listing; image / video / audio / PDF iframe, text fetched and shown in a `<pre>`; only for items whose `preview` is set), the `Unfinished uploads` card (`useUnfinishedUploads`, `unfinished-uploads.tsx`; uploading the same name + size into the same folder resumes automatically) and the upload queue `useUploads` (`hooks/use-uploads.ts`, one file at a time; a large file stays `processing` until `onBackgroundTaskFinished` — the window event BackgroundTaskListener re-sends — reports its `media.process` task, which also refreshes the listing).
- Thumbnails + durations (MEDIA-11): `FileThumb` (`features/media/components/file-thumb.tsx`) shows `thumbnail_url` or the file icon in Files, the file picker and the evidence files field; `formatFileSize` adds width × height and `formatDuration`. They arrive from a background job after the upload, so `useMediaList` polls (`useApiData` `refetchInterval(rows)`) while `awaitingMediaInfo` (`lib/media-info.ts`) finds a file updated in the last 30 s still missing them.
- Trash (`app/admin/files/trash`, `features/media/components/trash-browser.tsx`, `hooks/use-trash.ts`): `media/trash/list` (rows show `FileThumb`, MEDIA-12) with restore / delete forever / empty behind `media.trash-*` permissions; actions invalidate both the trash and the folder listings. Reached from the Files screen's **Trash** link.
- Admin search (`app/admin/(panel)/search`, `features/content/components/search-results.tsx`): Articles and Categories groups (private ones marked, public ones open the public site in a new tab via `publicPaths`) plus a Files group (SEARCH-01) whose rows link to their folder with `filesHref` (`features/media/lib/media-paths.ts`). Files screen column "Used in" reads `used_in` (categories attaching the file, articles embedding it). The dashboard shows total views and the `most_read` / `most_saved` rankings of `dashboard/summary`.
- Audit log screen (`app/admin/audit-log`, `features/history/components/audit-log-browser.tsx`): read-only table on `audit-log/list` (not `ResourceListPage`, which assumes create/edit/delete), newest first, filters by type (`AUDITABLE_TYPES`), event, actor (only with `admin-mst.list`) and dates (`YYYY-MM-DD` from the input → `d/m/Y` for the API); each row's changes reuse `Changes` from `history-viewer.tsx`.
- i18n: `messages/en.json` via next-intl; every user-facing string goes through `useTranslations`; `src/i18n/messages.test.ts` fails when a literal key (`t('x.y')`) is missing from `en.json` (template keys are not checked).
- Permissions (ADR-0013): `usePermissions().can('<feature>.<action>')` reads `user.permissions` from `credential/me`. `ResourceListPage` derives the feature from its endpoint's last segment and hides create / edit / delete (and row selection) without `store` / `update` / `delete`; menu entries carry a `permission` and `filterMenu` drops the rest (`src/shared/utils/permissions.ts`). Hiding is cosmetic, the API answers 403. `AuthProvider` reloads `credential/me` when the tab becomes visible and on any 403 (`apiClient.onForbidden`), at most every `USER_REFRESH_MIN_INTERVAL_MS`, so role changes show without a reload. Roles screen: `app/admin/roles` + `features/master/components/{role-form,permission-matrix}.tsx`.
- Signed-in devices (AUTH-04): `app/admin/sessions` + `features/master/components/session-list.tsx`, reached from the header's user menu (no sidebar entry, no permission: every admin manages their own sessions). `useAdminSessions` / `useAdminSessionActions` (`hooks/use-admin-sessions.ts`) on `admin-session/{list,delete,delete-others}`; `describeUserAgent` (`lib/user-agent.ts`) names browser + system. The current device has no sign-out button there (it uses Logout). Remember me (AUTH-05): the login page sends `remember`; `proxy.ts` also lets `/admin/*` through with `REMEMBER_COOKIE_NAME` (the API signs the device in again); `apiClient` refetches the CSRF cookie and retries a request once on a 419 (the new session's token).

## API contract

Responses are wrapped: `{ data, error: { status, code, messages } }`. Read server errors from `error.messages` (string or field map), never `response.data.message`. Lists are Laravel resource collections inside `data`: `{ data: T[], links, meta }`, typed as `PaginatedResponse<T>` (`src/shared/types/api.ts`) from the generated `PaginationLinks` / `PaginationMeta`; `getPaginationInfo` reads `meta` (`from` / `to` are null on an empty page).
