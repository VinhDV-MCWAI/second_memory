## 4. Observations (no change asked)

- **Level dates cannot be in the future** (`before_or_equal:today`): the US-1 scenario's dates (2026-11-01, 2026-12-01) cannot be entered on 2026-10-09; the check ran with past dates. Reasonable for a history; REQ-002 did not say either way.
- **Imported title = file name** when the note has no `title` (ADR-0010 contract), not the first heading. Matches Obsidian, where the file name is the note title.
- **Public pages are cached for up to 60 s** (P3-12, protects the per-IP rate limit): a level change appeared on `/skills/laravel` on the first request after the window. Fine for recruiters; worth one line in the release notes.

> 🇻🇳 Ghi nhận (không yêu cầu sửa): ngày đổi level không được ở tương lai; tiêu đề note import mặc định là tên file (đúng ADR-0010, cũng là tiêu đề trong Obsidian); trang public cache tối đa 60 giây.

## 5. Missing automated tests

- Importer default API URL against the real Compose port (BUG-01 would have been caught by a test that reads the nginx port, or by `make import` in E2E).
- Search ranking with a title match and a summary match for the same words (BUG-04).
- Header shows the signed-in admin (BUG-03).

> 🇻🇳 Test tự động còn thiếu: URL mặc định của importer so với cổng thật; thứ tự xếp hạng search; header hiển thị đúng người đăng nhập.

## 6. PO review (Lan)

**Decision: accepted with follow-ups.** Every Must (US-1 skills and levels, US-2 evidence, US-3 public page) and every Should / Could works as asked, and my top priorities hold: nothing private reached the public page or its API, history is append-only, and the importer never touched what I typed in the admin.

Before `v2.1.0` goes out:
- **BUG-03** — the release is something I will demo; a header with the wrong person's name and an image from a third-party site is not acceptable in front of anyone.
- **BUG-01** — the runbook is how I import; it must work without a hidden variable.

After the release (next phase is fine): BUG-02, BUG-04.

**Coaching (sealed brief revealed).** The brief held five acceptance criteria (three-entry history, no private data on the public page, goal auto-achieve, idempotent import, accent-free search); the clarification log uncovered all six hidden facts (scale, links only, public fields, importer rules, search, goals), and the requirement turned each into a testable scenario — well done. Questions that would have saved work: *how fresh must the public page be* (the 60 s cache was a design choice nobody asked me about), *may a level change be dated in the future* (the written scenario uses future dates), and *what is a note's title* (heading or file name). Handled well: making a private skill indistinguishable from a missing one, and the cut line that kept goals and typo tolerance optional.

> 🇻🇳 PO **chấp nhận kèm việc tiếp theo**: các story Must/Should/Could đều đạt; không lộ dữ liệu riêng tư, lịch sử chỉ thêm, importer không ghi đè dữ liệu admin. Trước `v2.1.0` phải sửa BUG-03 (sẽ demo, header sai tên người không chấp nhận được) và BUG-01 (runbook import phải chạy được không cần biến ẩn). BUG-02, BUG-04 làm sau. Nhận xét: phần làm rõ yêu cầu đã khai thác đủ 6 dữ kiện ẩn; nên hỏi thêm về độ tươi của trang public, ngày đổi level ở tương lai, và tiêu đề note lấy từ đâu.
