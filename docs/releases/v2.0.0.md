# v2.0.0 — Slim down (2026-10-07)

> 🇻🇳 Cắt giảm: bỏ CMS, đơn giản hoá đăng nhập, phân quyền và lịch sử thay đổi.

The CMS era ends. Content now lives in Obsidian, so the content CMS and everything around it are removed; the custom JWT auth is replaced by Laravel Sanctum; the role → feature → API permission chain becomes two fixed roles; 14 history tables become one audit log. What is left is a small admin core (admins, roles, audit log, media storage) that the Skill Ledger (Phase 3) builds on.

> 🇻🇳 Kết thúc thời CMS. Nội dung đã chuyển sang Obsidian nên CMS và mọi thứ đi kèm bị xoá; JWT tự viết được thay bằng Sanctum; chuỗi phân quyền role → feature → API thành hai vai trò cố định; 14 bảng lịch sử thành một audit log. Còn lại một lõi admin nhỏ để Skill Ledger (Phase 3) xây tiếp.

Change request: [REQ-001](../requirements/REQ-001-slim-down.md). Design: [RFC-001](../design/RFC-001-slim-down.md). Decisions: [ADR-0003](../adr/0003-remove-cms-modules.md) (removal), [PRB-001](../problems/PRB-001-custom-jwt-auth.md) / [ADR-0004](../adr/0004-sanctum-spa-cookie-auth.md) (auth), [ADR-0005](../adr/0005-owner-viewer-roles.md) (roles), [ADR-0006](../adr/0006-audit-log.md) (audit log).

## Breaking changes

> 🇻🇳 Thay đổi phá vỡ tương thích.

| Area | Before (v1.x) | After (v2.0.0) |
|---|---|---|
| Removed modules | Sliders, banners, setting links, socials, end users, departments, policies, categories, entries, entry descriptions — admin pages, API and tables | Gone. Content is exported to Markdown with `v1.2.0` before upgrading |
| Public docs API | `/api/docs/*` | Gone (404). The docs site answers every `/docs/*` URL with a "content moved" page (HTTP 200) |
| File manager | `/admin/file-manager` explorer UI | Gone. Media API, `media_mgmt` and MinIO objects are kept |
| Auth | Custom JWT, access + refresh tokens, `POST /api/admin/credential/refresh`, token CRUD | Sanctum SPA session cookie: `GET /api/sanctum/csrf-cookie`, then `login` / `me` / `logout` under `/api/admin/credential/`. Refresh and token routes are gone; 5 failed logins lock for 15 min (`429` + `Retry-After`) |
| Permissions | Roles, features, APIs and their mappings (pages, API, 2 DB views, 2 triggers) | One `role` column on `admin_mst`: `owner` (read + write) or `viewer` (read only, writes → `403`). The last active owner cannot be demoted, deactivated or deleted (`422`) |
| History | 14 `*_hist` tables, `GET …/history` endpoints | One append-only `audit_log` (`created` / `updated` with changed fields only / `deleted`, plus `logged_in`, `logged_out`, `login_failed`), read at `GET /api/admin/audit-log/list` and shown under the admin edit form |
| Errors | HTML error pages possible on `api/*` | JSON only on `api/*` |

API routes: 143 → 20 (including framework routes). The OpenAPI document (`make openapi`) is the full contract.

> 🇻🇳 Route API: 143 → 20. Hợp đồng đầy đủ nằm trong tài liệu OpenAPI.

## Upgrade an existing environment

> 🇻🇳 Nâng cấp một môi trường đang chạy — làm đúng thứ tự.

The drop migrations destroy data on purpose. Follow this order:

1. Deploy `v1.2.0` and run the [content export runbook](../runbooks/content-export.md); archive the Markdown folder.
2. `make backup` (the restore point; `down()` of the drop migrations restores structure, not data).
3. Optional, for US-3: note the object count per MinIO bucket.
4. Deploy `v2.0.0`. One `php artisan migrate` runs, in order: drop the removed modules' tables (`…100001`–`…100004`), add `admin_mst.role` with a backfill (holders of the old root role → `owner`, everyone else `viewer`; if no one held it, the oldest active admin becomes `owner`) (`…100005`), drop the RBAC tables, views and triggers (`…100006`), create `audit_log` (`…100007`), copy `admin_mst_hist` into it (`…100008`), drop `admin_mst_hist` — this step refuses to run if a history row was not copied (`…100009`).
5. Session settings in `laravel-api/.env`: `SESSION_DRIVER=redis` (`database` also works) and `SESSION_DOMAIN` for the real host; set `SANCTUM_STATEFUL_DOMAINS` if the admin FE is served from a host other than `APP_URL` (`make setup` regenerates the file from `.env.example`). The old `LARAVEL_*_TOKEN_SECRET` variables can be deleted.
6. Smoke check: log in, open the admin list, edit an admin and see the change in its audit trail, log out; `/docs` shows the "content moved" page; MinIO object counts unchanged.

Every user has to log in again (old JWTs are not accepted).

**Rollback:** redeploy `v1.2.0` images **and** restore the backup from step 2. Rolling back migrations alone gives empty tables.

> 🇻🇳 Thứ tự: deploy `v1.2.0` và chạy runbook export → backup → deploy `v2.0.0` (một lần `migrate` chạy hết các bước) → cấu hình session/Sanctum → smoke check. Mọi người phải đăng nhập lại. Quay lui = deploy lại `v1.2.0` **và** restore backup; chỉ rollback migration thì bảng sẽ rỗng.

## Verification

> 🇻🇳 Kiểm tra hồi quy trước khi gắn tag.

- `make verify` green on the tagged commit (2026-10-08; code unchanged since `3e90988`): Pint (188 files), Larastan no errors, backend 79 passed (263 assertions), ESLint, tsc (both apps), Vitest 53 (15 files) with coverage 89.35 % (gate 80 %).
- Fresh database: `migrate:fresh` on `testing` runs all 61 migrations → 12 tables, 0 views, 0 triggers. Rolling back the 9 P2 migrations restores exactly the v1 shape (43 tables, 2 views, 2 triggers); migrating again gives 12 / 0 / 0.
- Manual flow through nginx with curl: CSRF cookie → owner login → me → create a viewer → edit it → audit trail shows `created` and `updated` (changed field only, no password) → viewer login → viewer list `200`, viewer write `403` → viewer logout → me `401` → owner deletes the viewer → `logged_in` events recorded → owner logout. `/admin` without a session → `307` to login; `/docs` and `/docs/a/b` → `200`; `/api/docs/category` → `404`.
