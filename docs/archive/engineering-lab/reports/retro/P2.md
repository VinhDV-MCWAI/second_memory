## What went well

> 🇻🇳 Điều làm tốt.

- **Slicing paid off.** Ten small slices, lowest risk first, each green before the next. Removing consumers first (FE, docs site) and the API after kept every commit buildable, and the dangerous ones (auth, roles) came when little code depended on them.
- **Expand / contract as separate migrations** made the audit log switch boring: backfill is idempotent, the contract migration refuses to run while a row is missing, and the whole chain rolls back to the exact v1 shape (43 / 2 / 2) on a fresh DB.
- **Intake found hidden needs early** (content export, keep the files, a "moved" page). They became P2-05b, US-3 and US-4 instead of surprises after the drop.
- **Tests caught real bugs on the way:** the navigation test found 3 sidebar links to deleted pages; the guard test made PRB-002 impossible to come back.

> 🇻🇳 Chia lát nhỏ, rủi ro thấp trước; expand/contract tách migration giúp chuyển audit log nhẹ nhàng; intake phát hiện nhu cầu ẩn từ sớm; test bắt được lỗi thật.

## What went badly

> 🇻🇳 Điều chưa tốt.

- **PRB-002: every test run before slice 7 wiped the dev database and dev Redis.** The setup looked right (`<env force>`) but the container environment won. It was found only because the dev DB was mysteriously empty. Lesson: an isolation rule needs a test that proves it, not a config line that claims it.
- **Two slips at commit time:** an FE commit first picked up backend deletions staged earlier (caught and redone before anything else); slice 2 was committed as WIP while the stack was down.
- **A wrong assumption reached the RFC:** "avatar upload uses the media API" was never true. Checking the code path (not the component name) during impact analysis would have caught it.
- **One metric was not measured:** the roadmap asks for startup time, but `scripts/metrics.sh` never measured it, so there is no before value.

> 🇻🇳 PRB-002: test đã xoá dữ liệu dev mỗi lần chạy; hai lỗi khi commit; một giả định sai lọt vào RFC; thiếu số đo thời gian khởi động.
