# docker / ops

- The PHP image carries `ffmpeg` (MEDIA-11: durations and thumbnails, run by the queue worker; +~180 MB, dev image 433 MB).
- `docker-compose.yml` services: `ml-postgres`, `ml-redis`, `ml-php` (php-fpm), `ml-queue` / `ml-scheduler` / `ml-reverb` (ADR-0014: same image and mount as ml-php, `entrypoint: php artisan`, start after ml-php is healthy so its entrypoint's composer install and migrations are done; `make workers-restart` reloads their code), `ml-nextjs`, `ml-public-site` (Astro, `public-site/Dockerfile`), `ml-nginx` (reverse proxy, host :81 → 8080 inside), `ml-minio` + `ml-minio-init` (bucket + lifecycle setup).
- Env: `../scripts/setup-env.sh` (`make setup`) generates `docker/.env`, `laravel-api/.env`, FE env. Never hand-edit generated secrets into tracked files.
- CI lives in `../ci/` (ADR-0016): `ci/check.sh` runs every gate on committed code in a throwaway Compose project `sm-ci` (`ci/compose.yml`: own Postgres + Redis, no ports, runs as the caller's UID); `ci/build.sh` builds the production images (`make tf-images` too). `.github/workflows/ci.yml` and `.gitlab-ci.yml` only call these scripts. `ci/deploy.sh` (`make cd`) is the local CD: check → build → `infra/tf.sh prod-like apply` → `e2e/run.sh prod-like`; nothing deploys from GitHub (the old blue-green `ci-cd/` was removed).
- CI/CD runs **locally only**; GitHub / GitLab run nothing on push or PR (manual dispatch only, owner's decision 2026-10-14; re-enabling: `ci/README.md`). `make verify` (dev containers, includes uncommitted work) or `make ci` (exactly what GitHub runs) is the gate before every PR.
- `backup/backup.sh` / `restore.sh` — PostgreSQL + MinIO backup. Test restore after any change.
- Conventions: `.claude/rules/infra.md`.
- Images are pinned to exact versions (P4-02); bump them on purpose, never back to a floating tag. No service runs as root: `ml-php` and the Next.js dev containers run as UID 1000 so files in the bind mounts stay the developer's (another host UID: build arg `UID` / `GID`); nginx is `nginx-unprivileged` listening on 8080 inside; MinIO runs as 1000 from `docker/minio/Dockerfile`; Redis must keep an exec-form `command` starting with `redis-server` so the entrypoint drops to the `redis` user. Files left root- or www-data-owned by older containers: `docker run --rm -v "$PWD/laravel-api":/app alpine:3.24 chown -R 1000:1000 /app/vendor /app/storage /app/bootstrap/cache`.
- Production targets (P4-03, built by `ci/build.sh` for `infra/` and CI): the API image runs `php artisan optimize` at container start (inline entrypoint — the build context `laravel-api/` cannot reach a script in `docker/`), so never bake Laravel caches at build time; the Next.js builder bakes `NEXT_PUBLIC_API_URL=/api` (same origin, one tag for every environment). Size table: `infra/README.md` §Production images.
- Next.js dev images install dependencies at build time and skip pnpm's run-time reinstall (`pnpm_config_verify_deps_before_run=false`): after a `pnpm-lock.yaml` change, rebuild with fresh anonymous `node_modules` volumes (`make up`, i.e. `--build --renew-anon-volumes`; without the renew the old modules stay). Add JS deps without a host pnpm: `docker run --rm -u 1000:1000 -e HOME=/tmp -v "$PWD":/repo -w /repo <ml-nextjs image> pnpm --filter nextjs-fe add <pkg> --lockfile-only` (same for `public-site`). The public site's dev image works the same way.
- Public site container listens on 4321 (fixed by `public-site/astro.config.mjs` and the nginx upstream); `PUBLIC_SITE_PORT_OUTSIDE_ENV` (default 3002) is only the host port. Its healthcheck is `/skills/healthz`, which never calls the API (nginx waits for this container). Its dev image chowns `node_modules` to UID 1000 because Vite writes its cache there. Production image: everything bundled into `dist/`, no `node_modules`.
- nginx redirects `/docs…` to `/skills` (301, relative), sends `/skills`, `/skills/…` and Vite's dev files (`/@vite/`, `/@id/`, `/@fs/`, `/src/`, `/node_modules/`) to the public site, `/api/` to PHP-FPM, `/app/` to Reverb (WebSocket upgrade), `/media-official/` to MinIO (presigned URLs only, `Host` passed unchanged so signatures match, no body size cap; ADR-0014), everything else to the admin FE. MinIO buckets allow no anonymous access; the official bucket is versioned and noncurrent versions expire after 30 days (the file trash, MEDIA-07; the backend user may list and delete versions for restore / delete forever); re-run `docker compose up ml-minio-init` after editing `minio/create-buckets.sh`. The Terraform stack reuses the same file. After editing it: `docker exec ml-nginx nginx -t && docker exec ml-nginx nginx -s reload` works only when the file was changed in place. The config files are single-file bind mounts: `sed -i` and most editors write a new file (new inode), the container keeps the old one, and `docker restart ml-nginx` then fails on Docker Desktop (stale bind mount). Check with `docker exec ml-nginx grep … /etc/nginx/conf.d/default.conf`; if it is stale, recreate: `cd docker && docker compose up -d --no-deps --force-recreate ml-nginx` (BUG-02).
- Next.js dev runs Turbopack with native file watching (Turbopack's `watchOptions.pollIntervalMs` did not pick up changes in Docker). Keep the checkout on the Linux/WSL filesystem (e.g. `~/second_memory`, not `/mnt/c/...`) or hot reload won't see edits.
