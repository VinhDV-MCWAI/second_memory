# docker / ops

- The PHP image carries `ffmpeg` (MEDIA-11: durations and thumbnails, run by the queue worker; +~180 MB, dev image 433 MB).
- `docker-compose.yml` services: `ml-postgres`, `ml-redis`, `ml-php` (php-fpm), `ml-queue` / `ml-scheduler` / `ml-reverb` (ADR-0014: same image `my_lm-ml-php` (built once by ml-php; the workers have `image:` + `pull_policy: never`, no `build:`) and mount as ml-php, `entrypoint: php artisan`, start after ml-php is healthy so its entrypoint's composer install and migrations are done; `make workers-restart` reloads their code), `ml-nextjs`, `ml-public-site` (Astro, `public-site/Dockerfile`), `ml-nginx` (reverse proxy, host :81 → 8080 inside), `ml-minio` + `ml-minio-init` (bucket + lifecycle setup).
- Env: `../scripts/setup-env.sh` (`make setup`) generates `docker/.env`, `laravel-api/.env`, FE env. Never hand-edit generated secrets into tracked files.
- CI lives in `../ci/` (ADR-0016): `ci/check.sh` runs every gate on committed code in a throwaway Compose project `sm-ci` (`ci/compose.yml`: own Postgres + Redis, no ports, runs as the caller's UID); `ci/build.sh` builds the production images (`make tf-images` too). `.github/workflows/ci.yml` and `.gitlab-ci.yml` only call these scripts. `ci/deploy.sh` (`make cd`) is the local CD: check → build → `infra/tf.sh prod-like apply` → `e2e/run.sh prod-like`; nothing deploys from GitHub (the old blue-green `ci-cd/` was removed).
- CI/CD runs **locally only**; GitHub / GitLab run nothing on push or PR (manual dispatch only, owner's decision 2026-10-14; re-enabling: `ci/README.md`). `make verify` (dev containers, includes uncommitted work) or `make ci` (exactly what GitHub runs) is the gate before every PR.
- `backup/backup.sh` / `restore.sh` — PostgreSQL + MinIO backup. Test restore after any change.
- Conventions: `.claude/rules/infra.md`.
- Images are pinned to exact versions (P4-02); bump them on purpose, never back to a floating tag. No service runs as root: `ml-php` and the Next.js dev containers run as UID 1000 so files in the bind mounts stay the developer's (another host UID: build arg `UID` / `GID`); nginx is `nginx-unprivileged` listening on 8080 inside; MinIO runs as 1000 from `docker/minio/Dockerfile`; Redis writes its password into `/tmp/redis-auth.conf` at start (never on the command line; `rm -f` it first, because on a restart the old redis-owned file is still there and `fs.protected_regular` stops root from rewriting it in the sticky `/tmp`) and must end in `exec docker-entrypoint.sh redis-server …` so the entrypoint drops to the `redis` user; the healthcheck passes the password through `REDISCLI_AUTH`.
- Bind mounts are **folders, never single files** (incident 2026-10-20): Docker Desktop + WSL stages a single-file mount (and a short-syntax folder next to a named volume) under `/run/desktop/mnt/host/wsl/docker-desktop-bind-mounts/`, which is gone after WSL restarts, so the container fails with exit 127. Next to a named volume use the long syntax with `bind.create_host_path: false` (ml-postgres, ml-redis). Check: `docker inspect <c> --format '{{json .HostConfig.Binds}}{{range .HostConfig.Mounts}}{{.Source}}{{end}}'` must not show `docker-desktop-bind-mounts`. `docker/laravel/` is mounted at `/opt/ml-docker` (entrypoint + `php.ini` via `PHP_INI_SCAN_DIR`), `docker/nginx/` at `/etc/nginx/custom` (`nginx -c`), and paths inside these configs are absolute. Files left root- or www-data-owned by older containers: `docker run --rm -v "$PWD/laravel-api":/app alpine:3.24 chown -R 1000:1000 /app/vendor /app/storage /app/bootstrap/cache`.
- Production targets (P4-03, built by `ci/build.sh` for `infra/` and CI): the API image runs `php artisan optimize` at container start (inline entrypoint — the build context `laravel-api/` cannot reach a script in `docker/`), so never bake Laravel caches at build time; the Next.js builder bakes `NEXT_PUBLIC_API_URL=/api` (same origin, one tag for every environment). Size table: `infra/README.md` §Production images.
- Next.js dev images install dependencies at build time and skip pnpm's run-time reinstall (`pnpm_config_verify_deps_before_run=false`): after a `pnpm-lock.yaml` change, rebuild with fresh anonymous `node_modules` volumes (`make up`, i.e. `--build --renew-anon-volumes`; without the renew the old modules stay). Add JS deps without a host pnpm: `docker run --rm -u 1000:1000 -e HOME=/tmp -v "$PWD":/repo -w /repo <ml-nextjs image> pnpm --filter nextjs-fe add <pkg> --lockfile-only` (same for `public-site`). The public site's dev image works the same way.
- Public site container listens on 4321 (fixed by `public-site/astro.config.mjs` and the nginx upstream); `PUBLIC_SITE_PORT_OUTSIDE_ENV` (default 3002) is only the host port. Its healthcheck is `/healthz`, which never calls the API (nginx waits for this container). Its dev image chowns `node_modules` to UID 1000 because Vite writes its cache there. Production image: everything bundled into `dist/`, no `node_modules`.
- nginx (ADR-0021) redirects `/docs…` to `/` and `/login` to `/admin/login` (301, relative), sends `/admin…`, `/__nextjs…`, `/_next/` and `/favicon.ico` to the admin FE and every other path to the public site (catch-all `location /`, which also serves Vite's dev files; the dotfile deny rule spares `/node_modules/.vite/`; `/health` is an exact match), `/api/` to PHP-FPM, `/app/` to Reverb (WebSocket upgrade), `/media-official/` to MinIO (presigned URLs only, `Host` passed unchanged so signatures match, no body size cap; ADR-0014). MinIO buckets allow no anonymous access; the official bucket is versioned and noncurrent versions expire after 30 days (the file trash, MEDIA-07; the backend user may list and delete versions for restore / delete forever); re-run `docker compose up ml-minio-init` after editing `minio/create-buckets.sh`. The Terraform stack reuses the same file (uploaded to `/etc/nginx/custom/default.conf`, which `nginx.conf` includes). After editing it: `docker exec ml-nginx nginx -t && docker exec ml-nginx nginx -s reload` (the folder mount sees every edit, so the old stale-file problem BUG-02 is gone).
- Next.js dev runs Turbopack with native file watching (Turbopack's `watchOptions.pollIntervalMs` did not pick up changes in Docker). Keep the checkout on the Linux/WSL filesystem (e.g. `~/second_memory`, not `/mnt/c/...`) or hot reload won't see edits.
- Start / stop stability (2026-10-20, measured by cycling the stack): every healthcheck has `start_period` + `start_interval` (1–3 s) so dependents start as soon as a service is up (down → up 72 s → ~45 s, stop → start ~30 s); keep `interval` long for the steady state. Every service uses the `x-logging` anchor (json-file, 3 × 10 MB). Node containers and the PHP workers run with `init: true`: as PID 1 they ignored SIGTERM and were killed (exit 137) on every stop. The PHP entrypoint skips `composer install` while `vendor/.composer-lock.sha256` matches `composer.lock` (BusyBox `sha256sum -c -s`, no `--status`). `make up` / `make down` run `docker volume prune -f` (anonymous volumes only: `--renew-anon-volumes` leaves the old `node_modules` behind); daily use is `make start` / `make stop`. Memory limits follow measured use (idle stack ~1.5 GB); Redis `maxmemory` (192 MB) must stay under its container limit. Postgres WAL is capped for dev (`min_wal_size=80MB`, `max_wal_size=512MB`).
